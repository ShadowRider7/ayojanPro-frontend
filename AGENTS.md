# ayojanpro-frontend

A Next.js 16 App Router client for the AyojanPro event-service platform (single app under `src/app`, React 19.3, Tailwind CSS v4, Biome, Bun). No monorepo, no tests, no CI. The paired Express/Prisma backend lives in `C:\projects\AyojanPro`.

Clients plan events, professionals apply and get booked, and contracts, payments (bKash), deliverables, reviews and disputes are all managed through this UI. The most recent full review of both codebases — what was fixed and what is still open — is in `CODE_REVIEW.md`.

## Commands

- Package manager is Bun (`packageManager: bun@1.4.3`, committed `bun.lock`). Use `bun install` / `bunx`; don't add a second lockfile.
- `bun run dev` — dev server on :3000. It rewrites the auto-generated block at the top of this file and regenerates `.next/types`.
- `bun run lint` — `biome check`, **not** ESLint. `bun run format` runs `biome format --write`; `biome check --write` also applies safe lint fixes and import sorting.
- `bun run build` — production build; this is the only wired-up type check. For a standalone check use `bunx tsc --noEmit`.
- No test runner is configured. Don't assume `bun test`, Jest, or Vitest exist.

## Repo-specific gotchas

- `next.config.ts` enables `reactCompiler` (via `babel-plugin-react-compiler`) and static export (`output: "export"` in production). Read the matching guide in `node_modules/next/dist/docs/` before changing rendering or data fetching.
- Tailwind v4 is wired through the Turbopack loader in `next.config.ts` (`@tailwindcss/turbopack`), not PostCSS. There is deliberately no `postcss.config.*`; put Tailwind theme/CSS in `src/app/globals.css` (`@import "tailwindcss"`, `@theme`).
- Import alias is `@/*` → `src/*` (tsconfig `paths`).
- Types like `LayoutProps<"/">` in `src/app/layout.tsx` are generated by Next into `.next/types`; run dev/build before a standalone type check if they are missing.
- Biome defaults to LF and `biome.json` sets no `lineEnding`. On Windows checkouts with `core.autocrlf=true`, `bun run lint` currently reports a format diff on `package.json` (CRLF vs LF) — reformat it instead of assuming the lint config is broken.
- Forms validate with `validateOnChange(schema)` (`src/validation/validators.ts`), **not** `onSubmit`. TanStack Form keeps a validator's error until the same validator runs again, so a form-level `onSubmit` schema leaves a stale error on screen after the user fixes the field.
- The backend keeps **one** payment row per contract; its `stage` says which instalment it currently holds. `ContractDetail.tsx` derives the payment state from the stage — do not treat the row as "the latest payment".
- Guards live in one place: `src/components/auth/auth-guard.tsx` (`roles` and `requireApprovedProfessional` props). There is no separate role or professional-status guard.
- The professional application creates a **new** account, so it is only for visitors who are not signed in yet. Gate every "apply as a professional" call to action on `useCanApplyAsProfessional()` (`src/hooks/auth.hook.ts`) and wrap the application pages in `RedirectIfAuthenticated`.
- A dynamic route must export `generateStaticParams()` and it must not return an empty array — a static export has no runtime to render the route on demand, and Next.js fails the build with "With `output: export`, at least one route must be generated". Use `staticExportParams()` from `src/lib/static-params.ts`.
- Back buttons go back through the browser history, not to a fixed route. Use the shared `BackButton` (`src/components/shared/back-button.tsx`) and pass the fixed route as `fallbackHref` — it is only used when the visitor opened the page directly.
